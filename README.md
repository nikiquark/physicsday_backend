# ФизФест — сайт фестиваля

Сайт фестиваля науки «ФизФест» физического факультета НГУ: [physicsday.ru](https://physicsday.ru).

Один репозиторий на весь проект:

| Папка       | Что внутри                                                        |
|-------------|-------------------------------------------------------------------|
| `backend/`  | Django: админка, API, база данных, заявки участников              |
| `frontend/` | Next.js: сам сайт                                                 |

---

# Часть 1. Для организаторов: как поменять содержимое сайта

Почти всё, что видно на сайте, правится через админку — без разработчика
и без выкладки новой версии.

**Адрес админки:** `https://physicsday.ru/admin/`
Логин и пароль выдаёт администратор сайта.

> **Когда правка появится на сайте?**
> В течение минуты. Обновите страницу через минуту после сохранения —
> если ничего не изменилось, обновите ещё раз с очисткой кеша
> (Ctrl+F5 / Cmd+Shift+R).

## 1.1. Дата фестиваля, тексты, контакты

Раздел **«Содержимое сайта → Настройки сайта»**. Он один, разделён на группы:

- **Фестиваль** — дата, время начала, место, описание на главной странице.
- **Олимпиады** — даты проведения, формат, срок подведения итогов,
  а также два выключателя: показывать ли итоги олимпиады и блок про
  церемонию награждения.
- **Контакты** — ФИО, email, телефон организатора, подпись в подвале.
  Эти же данные показываются в окне «Контакты» в шапке сайта.
- **Персональные данные** — текст согласия под формами регистрации
  и ссылка на политику обработки. Ссылка показывается ещё и в баннере
  про cookie: если поле пустое, ссылки в баннере просто не будет.

## 1.2. Открыть и закрыть регистрацию

Раздел **«Содержимое сайта → Регистрация: разделы»**. Пять строк:
ФизФест, Мастер-классы, Экскурсии, Олимпиады, Конкурс рисунков.
В колонке «Сейчас» видно текущее состояние: *ещё не открыта*,
*открыта*, *закрыта*.

У каждого раздела:

| Поле                       | Зачем                                                         |
|----------------------------|---------------------------------------------------------------|
| **Открытие регистрации**   | Дата и время (новосибирское), когда форма появится сама        |
| **Закрытие регистрации**   | Когда форма исчезнет сама                                      |
| **Закрыть принудительно**  | Рубильник: перекрывает даты, закрывает приём прямо сейчас      |
| **Заголовок вместо формы** | Что написано вместо формы, например «Регистрация закрыта»      |
| **Текст до открытия**      | Например «Регистрация откроется 14 сентября»                   |
| **Текст после закрытия**   | Например «Регистрация завершена»                               |

Если **«Текст до открытия»** оставить пустым, он соберётся из даты
автоматически: «Регистрация откроется 14 сентября».

Даты нужны, чтобы никто не сидел у компьютера в 10:00, когда закрывается
приём заявок на олимпиады. Рубильник — на случай «мест не осталось,
закрываем сейчас».

> Закрытие проверяется и на сервере: вкладка, открытая до срока,
> не сможет отправить заявку после него.

## 1.3. Плитки программы, партнёры, соцсети

- **«Содержимое сайта → Программа: плитки»** — картинки и подписи в блоке
  «Программа» на главной. Колонка «Порядок» задаёт последовательность,
  «Показывать» — временно спрятать плитку, не удаляя её. Поле «Ссылка»
  делает плитку кликабельной (например `/masters`).
- **«Содержимое сайта → Партнёры»** — логотипы внизу главной.
- **«Содержимое сайта → Соцсети»** — ссылки в подвале и в окне «Контакты».

## 1.4. Мастер-классы и экскурсии

Это не «содержимое», а мероприятия со счётчиком мест, поэтому они живут
в своих разделах:

- **«Мастер-классы → Мастер-классы»** — название, возраст, время,
  аудитория, лимит мест, порядок, картинка.
- **«Экскурсии → Институты»** — название, адрес, дата и время, лимит мест,
  картинка.

Лимит мест уменьшать ниже числа уже записавшихся не нужно — счётчик
свободных мест просто уйдёт в минус, а запись и так закроется.

Для экскурсий место занимает и сопровождающий, и каждый ребёнок:
взрослый с двумя детьми занимает три места из лимита.

## 1.5. Итоги олимпиады

1. **«Содержимое сайта → Итоги олимпиад»** → «Добавить»: год и списки
   победителей одним полем. Можно вставлять HTML-теги: `<h3>`, `<h4>`,
   `<ul>`, `<li>`, `<b>`.
2. Поставьте галочку **«Опубликовано»**.
3. В **«Настройках сайта»** включите **«Показывать итоги олимпиады»** —
   тогда на странице олимпиад появится и кнопка «Итоги олимпиады»,
   и сам список.
4. Блок про церемонию награждения включается отдельной галочкой
   **«Показывать блок о церемонии награждения»**, текст — в поле рядом.

На сайте показывается самый свежий опубликованный год. Прошлогодние
итоги остаются в базе и не теряются.

## 1.6. Выгрузка списков участников в Excel

1. Откройте раздел с заявками: **«Мастер-классы → Участники»**,
   **«Экскурсии → Участники»**, **«Олимпиады → Участники»** или
   **«Physicsday event → Участники»**.
2. Кнопка **«Экспорт»** справа сверху.
3. Выберите формат — для Excel это **xlsx** (подойдёт и **csv**).
4. Нажмите «Отправить». Файл скачается.

Чтобы выгрузить участников одного мастер-класса или института,
сначала отфильтруйте список фильтром справа, потом жмите «Экспорт»:
выгрузится только отфильтрованное.

## 1.7. Работы на конкурс рисунков

Заявки лежат в разделе **«Конкурс рисунков → Работы на конкурс»**.
В списке видны миниатюра, автор, возраст, город и дата; по клику
открывается работа целиком и ссылка на оригинал файла.

- Возраст **красным** — автор не попадает в условия конкурса (5–17 лет).
  Такие заявки форма всё равно принимает, решение за жюри. Фильтр
  справа «Возраст → Вне условий конкурса» покажет только их.
- Айфон снимает в формате HEIC — такие файлы браузер не показывает,
  вместо миниатюры будет серая плашка со ссылкой «скачать».
- Галочка «Опубликовано» пока ни на что на сайте не влияет: галереи
  работ на сайте нет, поле заведено на будущее. Заметки жюри — в поле
  «Заметка жюри».
- Выгрузка списка — кнопкой «Экспорт», как у остальных заявок;
  в файле есть колонка со ссылкой на каждый рисунок.

Закрыть приём заявок: **«Регистрация: разделы → Конкурс рисунков»**,
там же дата закрытия (по умолчанию 27 сентября 2026, 13:00) и
принудительное закрытие.

Сами файлы лежат на сервере в каталоге `backend/media/contest_works/` —
если нужны все работы разом, проще забрать оттуда, чем скачивать
по одной.

## 1.8. Что править нельзя без разработчика

Вёрстка, блок «Участие в олимпиадах — это», тексты кнопок и сообщений
об ошибках, cookie-баннер, карта проезда. Если что-то из этого нужно
менять регулярно — скажите, вынесем в админку.

# Часть 2. Для разработчиков

## 2.1. Устройство

```
physicsday_backend/
├── backend/                 Django 5
│   ├── PhysicsDay/          настройки и корневые маршруты
│   ├── content/             редактируемое содержимое сайта + правила регистрации
│   ├── workshops/           мастер-классы и заявки на них
│   ├── excursions/          экскурсии в институты и заявки
│   ├── olympiads/           заявки на олимпиады
│   ├── physicsday_event/    заявки на сам фестиваль
│   ├── contest/             конкурс рисунков: заявки с файлами работ
│   └── media/seed/          картинки стартового каталога (в git)
├── frontend/                Next.js 15, App Router
│   └── src/
│       ├── app/             страницы; page.tsx — серверные, *Page.tsx — клиентские
│       ├── lib/content.ts   загрузка содержимого из Django
│       └── services/api.ts  запросы из браузера
├── docker-compose.yml       прод
├── docker-compose.dev.yml   разработка
└── .env.example             образец переменных окружения
```

### Граница между Django и содержимым

Правило простое: **если у сущности есть счётчик мест или связь
с участником — это обычное приложение Django (`workshops`,
`excursions`). Если это текст, картинка, дата или флаг — это
приложение `content`.**

Поэтому мастер-классы не переехали в `content`: их лимит проверяется
в транзакции при записи, и разносить каталог и заявки по разным
хранилищам значило бы сломать эту проверку.

### Адреса картинок

В API они приходят **путями от корня домена**: `/media/seed/program/institutes.jpg`.

Так сделано намеренно. Стандартное поле DRF собирает абсолютный адрес
из заголовка `Host`, а фронтенд запрашивает API дважды разными путями:
при серверном рендере — по внутреннему имени docker-сети `backend:8000`,
из браузера — по домену сайта. В первом случае в ответ попадал бы адрес
`http://backend:8000/media/...`, который браузер разрешить не может.

За это отвечают:

- `backend/content/fields.py` — поле `RelativeFileField`, отдаёт `value.url`
  вместо абсолютного адреса. Используется во всех сериализаторах с картинками;
- `frontend/src/lib/media.ts` — `toSitePath()`, сворачивает абсолютный адрес
  обратно в путь. Страховка на случай ответа из кеша, снятого раньше;
- `frontend/next.config.ts` — перенаправление `/media/` и `/static/` в Django
  для разработки и как запасной вариант, если в nginx нет этих блоков.

Добавляя новое поле с файлом, берите `RelativeFileField`, а не
`ImageField` — иначе внутреннее имя хоста снова уедет в браузер.

### Как содержимое попадает на сайт

`GET /api/content/` отдаёт одним ответом настройки, окна регистрации,
плитки, партнёров, соцсети, SEO и итоги олимпиад. Next запрашивает его
на сервере при рендере и кеширует на 60 секунд (ISR, `revalidate = 60`).
Поэтому правка в админке появляется на сайте без пересборки.

Если бэкенд не отвечает, страницы отдаются с запасным содержимым из
`frontend/src/lib/content.ts` — сайт не падает, но показывает
зашитые значения и закрытую регистрацию.

### Правила записи

- Человек определяется парой **нормализованное ФИО + email**:
  регистр, лишние пробелы и «ё» не создают нового участника,
  отчество — создаёт.
- **Один мастер-класс и одна экскурсия** на человека. Лимиты
  независимые: запись на мастер-класс не мешает записаться
  на экскурсию. ФизФест и олимпиады не ограничиваются.
- Проверка живёт в сериализаторах (`content/registration.py`),
  от гонки страхует `UniqueConstraint` в БД.
- Окно регистрации проверяется на сервере при приёме заявки,
  а не только скрытием формы.

## 2.2. Разработка

Нужен Docker и Docker Compose.

```bash
git clone git@github.com:nikiquark/physicsday_backend.git
cd physicsday_backend

docker compose -f docker-compose.dev.yml up --build
```

В другом терминале — первый запуск:

```bash
docker compose -f docker-compose.dev.yml exec backend python manage.py migrate
docker compose -f docker-compose.dev.yml exec backend python manage.py seed
docker compose -f docker-compose.dev.yml exec backend python manage.py createsuperuser
```

Готово:

- сайт — http://localhost:3000
- админка — http://localhost:8000/admin/
- API — http://localhost:8000/api/content/
- Postgres — `localhost:5442`, база/пользователь/пароль по умолчанию `physicsday`

Исходники смонтированы с хоста: Django перезапускается сам, Next
обновляет страницу без пересборки. `.env` для разработки не обязателен —
у всех переменных есть значения по умолчанию.

### Тесты и проверки

```bash
# бэкенд
docker compose -f docker-compose.dev.yml exec backend python manage.py test

# фронтенд: типы и ESLint
cd frontend && npm run check

# фронтенд: логика согласия на cookie и адресов файлов
cd frontend && npm test
```

`npm run check` обязателен перед выкладкой: `next build` внутри образа
типы больше не проверяет.

Покрыты нормализация ФИО, окна регистрации, правило «один мастер-класс
и одна экскурсия», лимиты мест и отсечение заявок после дедлайна.

### Миграции

```bash
docker compose -f docker-compose.dev.yml exec backend python manage.py makemigrations
```

Миграции **хранятся в git** и коммитятся вместе с изменением моделей.

## 2.3. Развёртывание

На сервере: Docker, внешний nginx и certbot на хосте (не в контейнерах).

### Первый запуск

Каталог может быть любым — важно лишь, чтобы nginx мог в него зайти
(`/opt`, `/var/www` подходят; домашние каталоги обычно нет). Дальше по
тексту путь подставляется из переменной, чтобы его не пришлось править
в трёх местах:

```bash
export PHYSICSDAY_DIR=/opt/physicsday     # подставьте свой путь

git clone git@github.com:nikiquark/physicsday_backend.git "$PHYSICSDAY_DIR"
cd "$PHYSICSDAY_DIR"

cp .env.example .env
# Заполните .env: DJANGO_SECRET_KEY, POSTGRES_PASSWORD, SITE_URL, домены.
python3 -c "import secrets; print(secrets.token_urlsafe(50))"   # для SECRET_KEY

docker compose up -d --build

docker compose exec backend python manage.py migrate
docker compose exec backend python manage.py seed
docker compose exec backend python manage.py createsuperuser
```

Наружу ничего не публикуется: `backend` слушает `127.0.0.1:8000`,
`frontend` — `127.0.0.1:3000`, Postgres не публикуется вовсе.

Если эти порты на сервере заняты, поменяйте `BACKEND_PORT` и
`FRONTEND_PORT` в `.env` — и не забудьте поправить `proxy_pass`
в конфигурации nginx ниже. Адрес привязки менять нельзя: `127.0.0.1`
зашит намеренно, чтобы контейнеры не оказались доступны из интернета
в обход nginx. Порты **внутри** контейнеров остаются 8000 и 3000 —
на них ссылается `API_URL_INTERNAL`, трогать их не нужно.

### nginx

```nginx
server {
    listen 443 ssl http2;
    server_name physicsday.ru;

    ssl_certificate     /etc/letsencrypt/live/physicsday.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/physicsday.ru/privkey.pem;

    client_max_body_size 20M;   # загрузка картинок через админку

    # Django: API и админка.
    # Порт должен совпадать с BACKEND_PORT из .env.
    location ~ ^/(api|admin)/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Статика админки и загруженные картинки — с диска, мимо Django.
    #
    # ПОДСТАВЬТЕ СВОЙ ПУТЬ. Ниже — пример для /opt/physicsday; узнать свой:
    #   cd каталог-проекта && pwd
    #
    # Не указывайте сюда путь к тому docker (/var/lib/docker/volumes/...):
    # у этого каталога права drwx--x--- root:docker, nginx работает
    # от www-data и получит на картинку 403.
    location /static/ {
        alias /opt/physicsday/backend/static/;
        expires 30d;
        access_log off;
    }
    location /media/ {
        alias /opt/physicsday/backend/media/;
        expires 7d;
        access_log off;
    }

    # Сам сайт. Порт должен совпадать с FRONTEND_PORT из .env.
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 443 ssl http2;
    server_name www.physicsday.ru;
    ssl_certificate     /etc/letsencrypt/live/physicsday.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/physicsday.ru/privkey.pem;
    return 301 https://physicsday.ru$request_uri;
}

server {
    listen 80;
    server_name physicsday.ru www.physicsday.ru;
    return 301 https://physicsday.ru$request_uri;
}
```

Блоки `/static/` и `/media/` не обязательны: без них запросы уходят
в Next, оттуда перенаправляются в Django, и всё работает — просто
медленнее. **Если получаете 403 на картинку — уберите эти два блока
и перезагрузите nginx, сайт сразу заработает**, а с путями разберётесь
отдельно.

Проверить, что nginx вообще может читать каталог:

```bash
sudo -u www-data ls "$PHYSICSDAY_DIR/backend/media/seed/program/" | head
```

Если тут `Permission denied`, дело не в nginx, а в правах на путь:
каждый каталог от корня до `media` должен быть доступен на вход
пользователю `www-data`. Домашние каталоги (`/root`, `/home/кто-то`)
для этого обычно закрыты — отсюда и совет клонировать в `/opt`.

### Автозапуск после перезагрузки

У сервисов стоит `restart: unless-stopped`, но сам compose надо поднять
после старта докера:

```ini
# /etc/systemd/system/physicsday.service
[Unit]
Description=ФизФест
Requires=docker.service
After=docker.service

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/physicsday
# ↑ подставьте свой путь
ExecStart=/usr/bin/docker compose up -d
ExecStop=/usr/bin/docker compose down

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now physicsday
```

## 2.4. Обновление

```bash
cd "$PHYSICSDAY_DIR"
git pull
docker compose up -d --build
docker compose exec backend python manage.py migrate
```

> **Перед выкладкой прогоните проверки — сборка образа их не делает:**
>
> ```bash
> cd frontend && npm run check && npm test
> cd ../backend && python manage.py test
> ```
>
> Проверка типов и ESLint вынесены из `next build` намеренно: они
> запускают отдельные процессы-воркеры и на сервере с 2 ГБ памяти
> вставали намертво, хотя сама компиляция занимает 16 секунд.
> Ошибка типов теперь не остановит сборку образа — её поймает
> только `npm run check`.

Миграции применяются **вручную**. В entrypoint их намеренно нет:
автомиграции на старте однажды ломают прод в самый неудачный момент.
`collectstatic`, наоборот, выполняется на каждом старте автоматически.

Команда `seed` при повторном запуске ничего не перезаписывает, так что
её можно вызвать повторно без риска потерять правки из админки.

### Откат

```bash
git log --oneline            # найти предыдущий коммит
git checkout <коммит>
docker compose up -d --build
```

Если новый релиз добавлял миграции, откат кода без отката базы может
не сработать — снимите дамп перед выкаткой.

### Резервные копии

Не настроены. Как минимум перед фестивалем стоит завести:

```bash
docker compose exec -T postgres pg_dump -U physicsday physicsday \
  | gzip > /var/backups/physicsday-$(date +%F).sql.gz
```

В базе лежат персональные данные несовершеннолетних — хранить дампы
нужно соответственно.

Загруженные картинки лежат в `backend/media/` обычным каталогом, так что
копируются просто:

```bash
tar czf /var/backups/physicsday-media-$(date +%F).tar.gz -C "$PHYSICSDAY_DIR" backend/media
```

Там же, в `backend/media/contest_works/`, лежат присланные на конкурс
рисунки — это работы детей, и второй копии у организаторов нет.

## 2.5. Cookie и согласие

Баннер предлагает два варианта — «Принять» и «Отклонить», — и отказ
действительно работает, а не просто прячет баннер.

Механизм в `frontend/src/lib/consent.ts`:

- решение **применяется на каждой загрузке страницы**, а не только
  в момент нажатия кнопки;
- при отказе удаляются все cookie, кроме строго необходимых, и
  очищается `localStorage`, кроме служебных ключей согласия;
- cookie, поставленная сторонним скриптом уже **после** отказа, будет
  удалена при следующей загрузке;
- пока посетитель не ответил, необязательные cookie тоже удаляются:
  ставить их до получения согласия нельзя;
- передумать можно в любой момент — ссылка «Настройки cookie» в подвале.

Согласие и отказ хранятся по-разному:

| Ответ     | Где хранится     | Как долго                                        |
|-----------|------------------|--------------------------------------------------|
| Принять   | `localStorage`   | постоянно — согласившегося переспрашивать незачем |
| Отклонить | `sessionStorage` | до закрытия вкладки — на следующий заход спросим снова |

Обновление страницы внутри одного визита отказ не сбрасывает, иначе
баннер выскакивал бы на каждый F5. Ответы из первой версии баннера
(ключ `cookiesAccepted`) распознаются: согласие принимается как есть,
отказ переносится в сессию, а старый ключ удаляется.

Строго необходимые cookie перечислены в `ESSENTIAL_COOKIES`:

| Cookie      | Зачем                                                     |
|-------------|-----------------------------------------------------------|
| `csrftoken` | защита форм от подделки запросов                          |
| `sessionid` | вход в админку (HttpOnly, из JavaScript недоступна)       |

Их отказ не удаляет: без них не отправить заявку и не войти в админку,
а на строго необходимые cookie требование о согласии не распространяется.

### Сторонние встраивания

Свои необязательные cookie сайт не ставит: аналитики в коде нет,
`csrftoken` выдаётся только на странице входа в админку. Шрифты
`next/font` подкладываются локально на этапе сборки, к Google
браузер не ходит.

А вот **карта Яндекса на главной ставит свои** — при загрузке виджета
приходит восемь cookie на домене `yandex.ru`, включая межсайтовый
идентификатор `yandexuid` со сроком жизни до 2028 года.

**Удалить их со стороны сайта невозможно.** Правило одного источника
не даёт странице `physicsday.ru` читать и стирать cookie домена
`yandex.ru` — `clearNonEssentialCookies()` их просто не видит.
Единственный способ соблюсти отказ — не загружать виджет.

Этим занимается [`MapEmbed`](frontend/src/components/ui/MapEmbed.tsx):
пока согласия нет, вместо карты показывается заглушка с адресом,
ссылкой «Открыть в Яндекс.Картах» (обычная ссылка, cookie не ставит)
и кнопкой «Показать карту» — разовая загрузка по осознанному действию,
сохранённое решение она не меняет.

Так же нужно поступать с любым будущим встраиванием: видео, виджет
сообщества, платёжная форма. Оборачивайте в проверку согласия, а не
надейтесь удалить чужие cookie задним числом.

### Как правильно добавить аналитику

Не вставляйте счётчик прямо в `layout.tsx` — он начнёт считать до того,
как посетитель ответил, и отказ окажется фикцией. Правильно так:

```tsx
"use client";
import { useEffect, useState } from "react";
import { CONSENT_CHANGE_EVENT, hasAnalyticsConsent } from "@/lib/consent";

export function Analytics() {
  const [allowed, setAllowed] = useState(false);

  useEffect(() => {
    const sync = () => setAllowed(hasAnalyticsConsent());
    sync();
    // Посетитель мог передумать, не перезагружая страницу.
    window.addEventListener(CONSENT_CHANGE_EVENT, sync);
    return () => window.removeEventListener(CONSENT_CHANGE_EVENT, sync);
  }, []);

  if (!allowed) return null;
  return <script src="..." async />;
}
```

И добавьте имя новой cookie в `ESSENTIAL_COOKIES`, **только** если без
неё сайт не работает. Счётчик посещений таким не является.

### Тесты

```bash
cd frontend && npm test
```

Проверяют механизм на поддельных `document`, `localStorage`
и `sessionStorage`: что отказ не попадает в `localStorage` и не переживает
закрытие вкладки, но не сбрасывается при обновлении страницы; что
необязательные cookie удаляются, а `csrftoken` и `sessionid` остаются;
что карта не грузится без согласия; что запрет браузера на хранение
данных не считается согласием.

## 2.6. Переменные окружения

Полный список с пояснениями — в `.env.example`. Три, о которые чаще всего
спотыкаются:

- **`DJANGO_ALLOWED_HOSTS`** обязан содержать `backend` — по этому имени
  в Django ходит серверный рендер фронтенда по внутренней docker-сети.
- **`NEXT_PUBLIC_API_BASE_URL`** — адрес API *из браузера*. На проде это
  относительный `/api`. Значение **вшивается в бандл при сборке**:
  поменять его на работающем контейнере нельзя, нужен
  `docker compose up -d --build frontend`.
- **`API_URL_INTERNAL`** — адрес API *из контейнера frontend*
  (`http://backend:8000/api`), мимо nginx и мимо интернета. Порт здесь
  внутренний, с `BACKEND_PORT` он не связан и меняться не должен.

## 2.7. Если что-то не работает

| Симптом                                   | Куда смотреть                                                                 |
|-------------------------------------------|-------------------------------------------------------------------------------|
| Админка без стилей                        | `docker compose logs backend` — прошёл ли `collectstatic`                      |
| Картинки не грузятся, nginx отдаёт 403    | `location /media/` указывает в `/var/lib/docker/volumes/...` — туда nginx не пускают. Путь должен вести в каталог проекта (`<путь>/backend/media/`); либо просто уберите блок |
| Картинки не грузятся, 404                 | Каталог `backend/media` в контейнере пуст. Проверьте, что в `docker-compose.yml` он смонтирован с хоста (`./backend/media:/app/media`), а не именованным томом: том создаётся пустым, картинок в образе нет |
| Команда из README сделала не то            | Почти во всех примерах путь берётся из `PHYSICSDAY_DIR`. Задайте его под свой каталог (`export PHYSICSDAY_DIR=$(pwd)` из корня проекта) — иначе docker молча создаст пустой каталог по чужому пути |
| Картинки не грузятся в разработке         | Протух кеш сборки Next: `docker compose -f docker-compose.dev.yml down && rm -rf frontend/.next && docker compose -f docker-compose.dev.yml up` |
| `EACCES` или `Permission denied` в `frontend/.next` | Контейнер писал от root. Задайте `DOCKER_UID`/`DOCKER_GID` в `.env`, затем `sudo rm -rf frontend/.next` |
| Сборка фронтенда встала, память под потолок | Серверу мало памяти. Проверки типов из сборки уже убраны; если встаёт и сама компиляция — добавьте своп: `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile` |
| Сайт показывает старую дату               | ISR-кеш, подождите минуту; если не помогло — `docker compose restart frontend` |
| Сайт показывает дату из `content.ts`      | Фронтенд не достучался до Django: проверьте `API_URL_INTERNAL` и `ALLOWED_HOSTS` |
| Форма отправляется, но приходит 403       | CSRF: проверьте `SITE_URL` и что nginx передаёт `X-Forwarded-Proto`            |
| Рисунок на конкурс не отправляется, 413   | Файл обрезал nginx. Форма пускает до 15 МБ, `client_max_body_size` в nginx — 20M. Поднимать лимит в форме (`contest/validators.py`, `MAX_FILE_SIZE`) можно только вместе с nginx |
| Рисунок не отправляется, 429              | Ограничение частоты: 10 заявок в час с одного адреса (`REST_FRAMEWORK` в `settings.py`). Обычно это школьный или домашний NAT — поднимите лимит на время приёма работ |
| «Регистрация закрыта», хотя должна идти   | Админка → «Регистрация: разделы» → колонка «Сейчас» и галочка «Закрыть принудительно» |
| Время закрытия не совпадает с объявленным | `TIME_ZONE` должен быть `Asia/Novosibirsk`, `TZ` в `.env` — тот же             |
| `address already in use` при `up`         | Порт занят другой программой. На проде задайте `BACKEND_PORT` / `FRONTEND_PORT`, для Postgres в разработке — `POSTGRES_DEV_PORT`; какой порт кем занят, покажет `ss -ltnp \| grep :5442` |
